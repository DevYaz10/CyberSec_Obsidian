
>[!quote] Definition
> *Server Side Request Forgery *(SSRF) is a web vulnerability where an attacker manipulates a vulnerable application to make requests to internal or external resources on behalf of the server. This can lead to data exposure, unauthorised access to internal systems, or service disruptions.

#### 2 Types of SSRF
- **Regular SSRF:** where data is returned to the attacker's screen.
- **Blind SSRF:** no data is returned to the attacker's screen.

A successful SSRF attack can result in any of the following: 
- Access to unauthorised areas.
- Access to customer/organisational data.
- Ability to Scale to internal networks.
- Reveal authentication tokens/credentials.

this one works in an interesting way

imagine the destination url is something like:
`Internal_URL = "http://" + server + ".website.thm/api/stock/item?id=" + id`
the expected case the url will turn like this 
http://api.website.thm/api/stock/item?id=123 

now if you tried to do something like 
http://website.thm/stock?server=api.website.thm/api/user&id=123

you will get this url with an error
`"http://"` + `api.website.thm/api/user` + `".website.thm/api/stock/item?id="` +`123`

as a hacker you don't want that and you want to ignore the hardcoded `.website.thm/api/stock/item?id=` part so what you can do is put a parameter behind it 
`&x=`
http://website.thm/stock?server=api.website.thm/api/user&x=&id=123

this way it will turn into this 
`"http://"` + **`api.website.thm/api/user?x=`** + `".website.thm/api/stock/item?id="` + `123`

notice how the hardcoded `".website.thm/api/stock/item?id="` turned into parametert `x=` and got ignored because there was no use for it and instead what got inside the `Internal_URL` was 
`api.website.thm/api/user`
